- **When to use**: delegate focused sub-tasks with clear goals and boundaries. Use the default mode for self-contained work that does not need the current conversation; use fork mode when inherited context is needed.
- **Recursion limit**: only the main agent may launch SubAgent. A child agent must not call SubAgent again; the runtime rejects nested launches.
- **When NOT to use**: do not delegate work that depends on a result you have not received yet, or duplicate work already assigned to a running child.
- **Fork mode**: pass `fork=true` to inherit parent session context (conversation history, plan, skills). Use when the child needs your working context.
- **Prompt design**: in default mode, provide a complete, self-contained task with the required paths, context, constraints, and expected result. In fork mode, state the focused task and any additional information it needs. Assign disjoint write scopes to concurrent children and keep dependent edits ordered.
- **Result handling**: when the child completes, its result is injected as a user message: `[sub-agent <id>] <status> (in=<n>, out=<n>)
Thinking: ...
Text: ...`. You then get another LLM turn to interpret and act on it.
- **Parallelism**: start independent SubAgent tasks together in one response. While they run, continue useful independent work that has not been delegated; do not duplicate their work. Results arrive asynchronously: process completed results when useful, but wait for every result needed by a dependent action or final conclusion. Match results by session_id; do not relaunch a task merely because another child finished first.
- **Failure**: if the child fails (status=failed), the result text may be partial or empty. Handle gracefully — do not retry automatically.
