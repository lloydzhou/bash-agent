### 3. 消息队列架构 (Go channel / Rust mpsc)

**状态**: 待复刻

**说明**: bash 使用 FIFO 文件实现主 agent 与子 agent 的通信，Go/Rust 使用原生并发消息队列

**架构对比**:
```
bash 版本 (FIFO 文件):
  interactive_mode → write FIFO → main_loop ← read FIFO
                                    ↓
                               agent_loop / handle_sub_agent_result
                                    ↑
  子 agent (后台进程) → write FIFO ─┘

Go/Rust 版本 (消息队列):
  interactive_mode → channel/mpsc → main_loop ← channel/mpsc
                                       ↓
                                  agent_loop / handle_sub_agent_result
                                       ↑
  子 agent (goroutine/thread) → channel/mpsc ─┘
```

**消息类型**:
```go
// Go
type MainLoopMessage struct {
    Type      string // "USER_INPUT" or "AGENT_RESULT"
    Input     string // USER_INPUT 的内容
    SessionID string // AGENT_RESULT 的子 session ID
    Status    string // "ok" or "failed"
    Result    string // 子 agent 执行结果
    InTokens  int    // 输入 token 数
    OutTokens int    // 输出 token 数
}
```

```rust
    },
}
```

```go
type MainLoopMessage struct {
    Type      string
    Input     string
    SessionID string
    Status    string
    Result    string
    InTokens  int
    OutTokens int

func (rt *runtime) mainLoop() error {
    for msg := range rt.msgChan {
        switch msg.Type {
        case "USER_INPUT":
            if err := rt.agentLoop(msg.Input); err != nil {
                rt.error("%v", err)
            }
        case "AGENT_RESULT":
            rt.handleSubAgentResult(msg)
        }
        // 非交互模式且无活跃子 agent 时退出
        if !rt.cfg.Interactive && rt.activeSubCount == 0 {
            break
        }
    }
    return nil
}

// interactiveMode 中:
func (rt *runtime) interactiveMode() error {
    // ... 初始化 ...
    go func() {
        defer close(rt.msgChan)
        for {
            line, err := readline(...)
            if err != nil {
                break
            }
            rt.msgChan <- MainLoopMessage{Type: "USER_INPUT", Input: line}
        }
    }()
    return rt.mainLoop()
}
```

```rust
enum MainLoopMessage {
    UserInput { input: String },
    AgentResult {
        session_id: String,
        status: String,
        result: String,
        in_tokens: usize,
        out_tokens: usize,
    },
}

fn main_loop(&mut self) -> Result<()> {
    while let Ok(msg) = self.msg_rx.recv() {
        match msg {
            MainLoopMessage::UserInput { input } => {
                if let Err(e) = self.agent_loop(input) {
                    self.error(&e.to_string());
                }
            }
            MainLoopMessage::AgentResult { session_id, status, result, in_tokens, out_tokens } => {
                self.handle_sub_agent_result(&session_id, &status, &result, in_tokens, out_tokens)?;
            }
        }
        if !self.cfg.interactive && self.active_sub_count == 0 {
            break;
        }
    }
    Ok(())
}

// interactive_mode 中:
fn interactive_mode(&mut self) -> Result<()> {
    let tx = self.msg_tx.clone();
    std::thread::spawn(move || {
        loop {
            let line = readline("> ");
            if line.is_err() {
                break;
            }
            if tx.send(MainLoopMessage::UserInput { input: line.unwrap() }).is_err() {
                break;
            }
        }
    });
    self.main_loop()
}
```

```go
func (rt *runtime) handleSubAgentResult(msg FifoMessage) {
    // 1. 记录 usage 事件
    usageEvt := map[string]any{
        "type": "usage",
        "input_tokens": msg.InTokens,
        "output_tokens": msg.OutTokens,
        "kind": "sub_agent",
        "sub_session_id": msg.SessionID,
    }
    _ = rt.appendEvent(usageEvt)
    
    // 2. 更新 stats
    stats := rt.readStats()
    stats["sub_agent_request_count"] = statsFloat64(stats, "sub_agent_request_count") + 1
    stats["total_input_tokens"] = statsFloat64(stats, "total_input_tokens") + float64(msg.InTokens)
    stats["total_output_tokens"] = statsFloat64(stats, "total_output_tokens") + float64(msg.OutTokens)
    rt.writeStats(stats)
    
    // 3. 记录 sub_agent_end 事件
    _ = rt.appendEvent(map[string]any{
        "type": "sub_agent_end",
        "session_id": msg.SessionID,
        "timestamp": time.Now().UTC().Format(time.RFC3339),
        "status": msg.Status,
    })
    
    // 4. 更新活跃子 agent 计数
    rt.activeSubCount--
    
    // 5. 显示结果
    if rt.isStreamJSONMode() {
        _ = rt.emitStream(map[string]any{
            "type": "sub_agent_result",
            "session_id": msg.SessionID,
            "status": msg.Status,
            "input_tokens": msg.InTokens,
            "output_tokens": msg.OutTokens,
        })
    } else {
        preview := truncateRunes(msg.Result, 120)
        if msg.Status == "ok" {
            fmt.Fprintf(rt.stderr, "\033[35m[sub-agent %s] completed (in=%d, out=%d)\033[0m\n", 
                msg.SessionID, msg.InTokens, msg.OutTokens)
        } else {
            fmt.Fprintf(rt.stderr, "\033[31m[sub-agent %s] failed\033[0m\n", msg.SessionID)
        }
        if preview != "" {
            fmt.Fprintf(rt.stderr, "\033[90m  %s\033[0m\n", preview)
        }
    }
    
    // 6. 注入结果到 conversation 并触发 agent loop
    context := fmt.Sprintf("[Sub-agent result | session_id=%s | status=%s | tokens_in=%d tokens_out=%d]\n%s",
        msg.SessionID, msg.Status, msg.InTokens, msg.OutTokens, msg.Result)
    _ = rt.agentLoop(context)
}
```

```rust
    pub msg_tx: mpsc::Sender<MainLoopMessage>,

fn sub_agent(&self, prompt: &str, description: &str, ctx: SubAgentContext) -> Result<String> {
    if prompt.is_empty() {
        bail!("Error: no prompt provided for sub-agent");
    }
    
    let sub_session_id = format!("sub_{}", generate_session_id());
    let prompt = prompt.to_string();
    let cwd = self.cwd.clone();
    let home = self.home.clone();
    let config = self.config.clone();
    let msg_tx = ctx.msg_tx.clone();
    
    // 启动后台线程
    std::thread::spawn(move || {
        // 1. 创建子 agent 的 conversation store
        let sub_paths = session::paths_for(&home, &cwd, &sub_session_id);
        session::ensure_dir(&sub_paths.session_dir).ok();
        let sub_conv = conversation::Store { path: sub_paths.conversation.clone() };
        sub_conv.ensure().ok();
        
        // 2. 执行 agent_loop
        let (result, status) = execute_sub_agent_loop(&prompt, &sub_conv, &sub_paths, &config);
        
        // 3. 收集 usage 统计
        let stats = read_stats(&sub_paths.stats);
        let in_tokens = stats_get_f64(&stats, "total_input_tokens") as usize;
        let out_tokens = stats_get_f64(&stats, "total_output_tokens") as usize;
        
        // 4. 通过消息队列发送结果
        let _ = msg_tx.send(MainLoopMessage::AgentResult {
            session_id: sub_session_id,
            status,
            result,
            in_tokens,
            out_tokens,
        });
    });
    
    Ok(format!("Sub-agent started: session_id={}", sub_session_id))
}
```

**说明**: 在系统提示词中新增 SubAgent 使用指南

**内容**:
```
<sub-agent-guidance>
- **When to use**: delegating independent sub-tasks that do NOT need your current conversation context — e.g. investigating a separate file, running a focused search, testing a hypothesis in isolation.
- **When NOT to use**: tasks that depend on your working context, conversation history, or intermediate state. The child agent starts with a blank slate.
- **Prompt design**: write a complete, self-contained prompt. Include all file paths, function names, error messages, and constraints the child needs. Assume zero shared context.
- **Result handling**: when the child completes, its result text is injected as a user message prefixed with `[Sub-agent result | session_id=... | status=ok|failed | tokens_in=... tokens_out=...]`. You then get another LLM turn to interpret and act on it.
- **Parallelism**: multiple SubAgent calls in one turn run concurrently. Use this to parallelize independent investigations.
- **Failure**: if the child fails (status=failed), the result text may be partial or empty. Handle gracefully — do not retry automatically.
</sub-agent-guidance>
```

## 不需要复刻的变更

### 1. write_message 缓冲优化
**原因**: bash 的 `printf` 在并发写入时会交叉输出，需要拼接后一次输出。Go/Rust 的 I/O 模型不同，不存在此问题。

### 2. SIGINT 中断处理改进 (FD 方式)
**原因**: bash 使用 FD 读取 LLM 流，SIGINT 时需要关闭 FD 来中断阻塞的 read。Go/Rust 使用 channel/AtomicBool 机制，已经是正确的。

### 3. 代码精简/空行移除
**原因**: 纯代码风格变更，不影响功能。

### 4. 文档变更 (docs/*.md)
**原因**: 文档已经更新，Go/Rust 代码需要实现的是功能本身。
